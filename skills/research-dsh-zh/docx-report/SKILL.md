# Docx Report - 模板化调研报告生成

## 触发方式

`/docx-report <模板.docx 路径> [输出目录]`

例：`/docx-report /root/Working/Macao/Output_Report/Report_Template/xxx.docx /root/Working/Macao/Output_Report`

## 适用场景

- 用户给出一份 **.docx 提纲/模板**，要求"结合 space 中的所有调研内容"生成一份**正式报告**。
- 需要交付 **Word 成品**（而非 Markdown），且对版式、引用、参考文献有明确要求。
- 工作区里已有大量一手/二手调研资料（`Interview_Research/`、`company-dossier/`、`*.md`、`*.csv`、PDF、截图），需要被系统性地"用起来"而不是重新调研。

不适用：纯 Markdown 报告、无模板的自由写作、单纯的资料汇总。

## 一、硬性要求（用户验收标准，必须逐条满足）

> 以下 R1–R16 是本 skill 的**验收口径**，不是建议。
> R1–R5 来自用户的明确反馈；**R6.1–R6.4** 借鉴《澳门科技企业AI价值场景调研COT-9.0-澳门科技特化版》的"物理确定性 / 调研量纲 / 专家基准 / 战略对齐偏离"四条准则（该文件为输入侧 COT，只取其数据可信度契约，不取其调研流水线与领域内容）；**R8** 取其"矛盾—场景映射"的筛选逻辑。

### R1 模板保真
先用 `unzip` 解开模板 `.docx`，从 `word/document.xml`、`word/styles.xml` 提取**样式基线**，逐项还原：

- `w:docDefaults`：默认字体、字号（`w:sz` 为半磅，22 = 11pt）、行距（`w:line` 288 = 1.2 倍）；
- 各级标题：字体（如 `等线`/`Arial`）、字号（章 32=16pt、节 24=12pt）、是否加粗、`outlineLvl`、段前段后间距；
- 页面：`w:pgSz`（A4 = 11905×16840 twips）、`w:pgMar` 页边距；
- 章节结构：**逐节对应模板提纲**，不得缺章、不得擅自改章序。

#### R1.2 架构图与图表（禁止用 ASCII 拼图）

**任何"架构/流程/分层"示意都必须出图，不得用 ``` 围栏里的 `┌─┐│└┘` 字符拼。**
原因：中文字体不是等宽字体，东亚字符是双宽，右框线永远对不齐；实测在 Word 里会**完全错位甚至内容消失**。

工序：
1. 写 JSON 规格（面板 title/subtitle/color/items/footer + 箭头 label），见 `assets/make_architecture_figure.py`；
2. `python3 assets/make_architecture_figure.py --spec figures/fig_X_Y.json` 生成 PNG（存 `figures/`）；
3. 底稿写 `![图 X-Y 说明](figures/fig_X_Y.png)`，**下一行**用 `*图 X-Y　说明（资料来源：…[[n]]）*` 作居中题注；
4. 图内文字语体**必须与文档一致**（繁體文档就写繁體）；图内不放引用角标，**引用写在题注里**（图内无法点击）。

#### R1.1 版式档（同一份底稿，两种版式）

本 skill 内置两个版式档，由 `md2docx.py --profile` 切换；`TEMPLATE_SPEC.md` 载有完整规格表：

| 档 | 语体 | 中文字体 | 字号 | 行距 | 段前 | 对齐 | 适用 |
|---|---|---|---|---|---|---|---|
| `research` | 简体 | 等线（西文 Arial） | 正文 11pt，章 16pt | 1.25 | 0 | 左对齐 | 研究/内部版 |
| `gov` | **繁體** | **標楷體**（西文 Times New Roman） | **全篇 14pt**（标题仅加粗，不放大） | **1.5** | **6pt** | **两端对齐** | 政府呈报版 |

`gov` 档对齐依据：科技厅《澳琴联动推进算力建设初步分析报告》（2026-08-25）实测规格——
`eastAsia=標楷體`(740/740)、`ascii=Times New Roman`、`sz=28` 全篇唯一、
`spacing before=120 line=360 auto`、`jc=both`、`ind firstLine=480`、`docGrid linePitch=360`、页脚页码。

> **两处有意偏离**（须在交付说明中写明）：
> ① **表格字号按档降级**（research 9.5pt／gov 11pt）——政府参照件没有宽表，本报告的 7 列对标表在 14pt 下会溢出；
> ② **页眉密级默认不加**：参照件页眉为「秘密」，但**密级应由发文机关决定**，故做成 `--classification "秘密"` 可选参数，默认留空。

**注意：切换版式档后必须回归验证 `research` 档未被污染**——profile 相关的默认参数必须写成 `size=None` 后在函数体内解析，否则 Python 在 def 时就把旧值绑死（真实踩过的坑）。

详见 `TEMPLATE_SPEC.md`。

### R2 禁止 Word 自动编号（最高优先级）
**绝对不要对列表使用 `List Number` / `List Bullet` 样式或写入 `<w:numPr>`。**
Word 会把全文档所有引用同一编号定义的段落视为**同一个序列**，导致打开后出现"整篇文档跨标题连续编号"的严重版式错误。

正确做法：列表一律渲染为**普通段落 + 字面量标记**：
- 有序：`1.` `2.` `3.` 作为文本写入，**每个列表独立从 1 重新计数**；
- 无序：`•` 作为文本写入；
- 用 `left_indent` + 负 `first_line_indent` 制造悬挂缩进。

### R3 引用角标必须可点击跳转
- 正文引用以上标形式呈现：`vertAlign=superscript`、正文字号的 ~0.8 倍、深蓝色（如 `#1F497D`）；
- 每个角标是 **内部超链接**（`<w:hyperlink w:anchor="_RefN">`），点击跳转到《参考文献》对应条目；
- **多编号引用必须逐个成链**：`[[1,2,5,20,42]]` 要渲染成 `[` + 链接1 + `,` + 链接2 + … + `]`，
  **每个数字各自是一条超链接**（分别指向 `_Ref1`、`_Ref2`、`_Ref5`…），**不得把整串做成一个指向首编号的链接**；
- 参考文献条目段落必须有对应书签 `<w:bookmarkStart w:name="_RefN">`，书签 id 全文档唯一；
- 交付前必须校验**所有 anchor 均有同名书签**（零失效链接），且**链接总数 ≈ 各引用编号个数之和**（而非角标段落数）。

### R4 参考文献必须详尽（**两级引用**）
每条条目按 **"原始链接 + 中间报告"** 两级给出（用户明确要求）：
1. **原始链接**——该事实的一手出处（政府公报/法规、机构官网、年报、公开报道），供读者独立核验；
   能取到 URL 就给 URL；取不到就**如实写"无（原因）"或`【待补】`**，**绝不以外推或相似链接代替**；
2. **中间报告**——本报告写作时**实际依据的调研成果**（`Interview_Research/` 下的专题深度调研报告、
   企业尽调报告、事实汇编、当前算力台账），并注明该源的**摘录落盘文件**（`sources/…`），
   供读者回溯"这条结论是怎么形成的"；
3. 附录开头必须写明**覆盖情况**（多少条有原始链接、多少条为自产报告/一手数据/内部文件、
   多少条`【待补】`），把缺口摆到明面上，而不是让读者以为是全覆盖。

### R4 原文条目要求（内容）
每条参考文献至少包含：**机构/作者 + 文件名/标题 + 文号或日期 +（如有）URL 或工作区落盘路径**。
- 按主题分组编号（国家战略 / 地方政策 / 法律法规 / 统计基础设施 / 企业与行业 / 本次调研既有成果 / 补充调研专题…）；
- **分组标签必须是标题（`#### 【一】…`），不是加粗正文**——否则不会出现在 Word 导航窗格的标题树里；
- 条目在 Markdown 中写作 `Rn. <内容>`，由转换器自动生成书签并渲染为 `[n] <内容>`；
- 附录末尾附一句"原始网页/PDF 与逐字摘录落盘位置"，保证可回溯。

### R5 重要判断、结论与表格数据都必须有引用
- 覆盖范围：**核心结论摘要、定位判断、各章小结、方案对比结论、模式价值、所有含数字/金额/法规编号的段落**；
- **表格同样必须挂角标**：关键数据速览表、统计表、对标表、判给台账、预测表的每一行数据，只要能定位到源，都要挂 `[[n]]`；**落位在"数值所在单元格"内，不是行末的来源/备注列**（见 R10-1，工序见 `assets/move_citations_to_value.py`）；同一格多源写作 `[[a,b]]`；
  - 转换器已支持表格内引用（`add_table(..., allow_cite=True, cite_size=8.0)`），角标按表内字号自动降级为 8pt；
  - 多行规则用脚本批量追加，不要手改（见 `assets/add_table_citations.py`）；
  - **推荐做法**：在"关键数据速览"表下加一句表注——"本表及各章表格中的上标数字为参考文献编号，点击可跳转至附录F对应条目"；
- **不允许存在"僵尸文献"**：参考文献表里的每一条都必须在正文或表格中被至少引用一次；交付前统计被引用编号集合，若 1..N 有缺口，要么补挂角标、要么删除该条目；
- 密度：达不到"每段都有"时，至少保证**所有结论性段落 100% 有角标**；
- 交付前用脚本统计"含结论/判断/建议/定位 等关键词的段落中有角标的比例"，必须为 **100%**。

### R6 证据纪律
- 分级：`official`（政府/公报/监管文件）＞ `company`（企业自述）＞ `media`（第三方媒体）＞ `inference`（推算）；
- **不编造**：拿不到就写"未取得/未公开（负面发现）"——负面发现与正面事实同等有价值；
- **口径矛盾并录**：两个官方口径不一致时并列呈现并注明差异，不得静默择一；
- 推算一律就地标注 `【推算】`，不与已核实事实混同。

> R6.1–R6.4 为**数据可信度契约**，借鉴自《澳门科技企业AI价值场景调研COT-9.0》的"量纲—公式—基准"体系：它解决的是"这个数字凭什么可信、别人能不能复算"。

#### R6.1 推算三件套（强制）
标 `【推算】` 只是起点，不是终点。任何推算必须同时给出：
1. **公式**——写在正文可见处（纯文本即可，如 `P ≈ QPS × T_total × M / η`），**不得只把公式留在底稿或子代理报告里**；
2. **参数取值**——每个入参的值 + 口径 + 来源角标（如 `QPS = 2（政府 Helpdesk 0.5–2 QPS/千用户 [[n]]）`）；
3. **基准/系数来源**——专家基准或行业默认值必须注明出处（如 `η = 0.6，来源 [[n]]`）。

> 唯一检验口径：**读者拿着报告能否自己复算出同一个数**。复算不出，就是三件套缺件。
> 系数与基准参数集中放《附录·调研方法与口径说明》（我方报告里的 A100 等效折算系数 `H800≈2.0×A100 / V100≈0.25×A100 / 寒武纪≈0.3×A100` 即此类），正文只引用不重复。

#### R6.2 量纲可复核（每个数字都要能回答"谁、被问了什么"）
正文每个关键数字必须可回答三问：
1. **量纲/单位**（A100 等效卡时/年、PFLOPS(FP16)、MOP/月…）；
2. **采集通道**（文件名 / 判给台账编号 / 问卷题号 / 访谈岗位）——推荐直接写成可复核句式：`请询问 <岗位>："<问题1>？<问题2>？"`；
3. **口径与年份**。

> 交付前抽查：任取 **10 个数字**逐个在 `sources/`、台账或问卷中定位原始出处；定位不到的，降级表述或改标 `【估算】`。

#### R6.3 量级护栏
- 每类推算给出**量级上下限**；越界必须**解释原因或拆分为子项**，不得直接给数；
- **禁止把"算术和"当"瞬时负载"**：典型坑是把 N 个场景/单位的峰值相加得出总需求（会系统性高估）。并集/峰值类数字必须显式注明"**非任一时点负载**"，并说明其中多少是客户侧/非自有资产。

#### R6.4 叙事—证据对照（自述必须交叉验证）
对任何主体（企业/机构/部门）的**自述能力**，必须列出三栏并给出判定：
- **支持证据**：可验证的合同、判给台账、收入贡献、专利/软著、在册认证；
- **不支持证据**：可核验的反证（如"10 个在招职位中 0 个 AI/算法岗""官网无该产品线的任何页面"）；
- **偏离判定**：叙事与证据是否匹配；偏离时必须写出结论句（如"AI 叙事强于 AI 编制"）。

> 禁止只转述自述：`company` 级证据**不得单独支撑结论性判断**，必须与 `official`/`media`/台账交叉后方可下结论。

#### R6.5 官方口径优先，差异入注（用户的明确要求）
当**官方口径**与企业自述、项目宣传、或本报告自建模型**不一致**时：
1. **正文以官方口径为准**（含政府文件、监管答覆、判给文件、执行机构会议口径）；
2. **差异不得静默丢弃**——必须在**注释、并录表或"差异说明"段**中写明：另一口径的数值、其来源、以及**差异成因**（时点不同／统计对象不同／精度口径未标／宣传口径 vs 现况口径）；
3. **测算类数字不混用**：口径不明（未标 FP16/INT8/定点、未标时点）的官方测算，**不得换算为卡数、机柜数或投资额**，应原样引用并标注"口径未标"；
4. 典型样板（本 skill 已固化）：横琴智算平台"**项目介绍口径（4 Eops 规划、2,390 台寒武纪、累计服务逾百家）**"vs"**执行机构现况口径（土建与配套基建已完成、尚未安装算力卡）**"——正文以**现况**为准，注释并列两口径与时点，并声明"当前可用算力测算不计入其规划算力"。

### R7 语言、用字与命名
- **语体随版式档**（R1.1）：`research` 档正文用**简体**；`gov` 档正文用**繁體**。转换用 `assets/to_traditional.py`，**不得手工逐字替换**；
- **繁体转换的三条红线**（违反即破坏可追溯性）：
  1. **不得用 `s2twp` 等台湾用语档**——会把 軟件→軟體、網絡→網路、數據→資料、芯片→晶片、視頻→影片，与港澳公文用字不符；
  2. **必须保护文件路径、URL、行内代码、`[[n]]`**——路径中的简体中文一旦被转成繁體就不再指向真实文件，直接违反 R10；
  3. **基线的选择顺序是"先字形、后语汇"**：
     - `s2hk` 保留港澳语汇（平台/後台）却输出**日式异体字**——说→説(U+8AAC)、启→啓(U+5553)、
       户→户(U+6237)、群→羣、峰→峯、税→税、温→温；`s2t` 同样给出 説明／啓動／爲／複覈／集羣；
     - `s2tw` **字形全部正确**（說/啟/戶/群/峰/稅/溫/脫/敘/衛/兌/閱/蘊/麵/複核），只是语汇为台湾用法（平臺/後臺）；
     - **故基线取 `s2tw`，再用覆盖表把语汇改回港澳**（平臺→平台、後臺→後台、溼→濕）。
     全篇对比两配置共 21 种差异字符：s2tw 更正确约 170 处，s2hk 更正确仅 台 146（全部来自「平台」）与 濕 3 ——
     精确改回这两项，净收益最大。用字须与政府参照件对齐（平台 13/平臺 0、數據 21/資料 2、支持 4/支援 0、人工智能 7/人工智慧 0）；
- **公司/机构名保留其登记的原文用字**（澳門机构名本身即繁體，须与简体正文并存而不被"归一化"）；
- 文件名建议 `<报告全名><YYYYMMDD>.docx`；**繁體版文件名亦用繁體**，与简体工作底稿并存。

### R8 问题—建议可追溯（建议不得悬空）
每条建议/方案必须显式锚回它要解决的**现状问题**，并用代价论证优先级：
- 建议段内回指问题所在章节（如"→ 见 3.4.1"）并挂该问题的引用角标；
- 必须给出**不解决的量化代价**（如"投标方案人工产出 X 人天/单 × 年 Y 单 = 浪费 Z 人年"），不得只用形容词；
- **交付物**：附录增一张 **「短板/问题 → 建议 → 量化代价 → 依据」映射表**，逐行挂角标。

> 这张表是"建议不悬空"与 R5 引用覆盖率的共同验收物；也是决策型报告最容易被追问的一张表。

### R9 问卷答案必须落进现状（"当前算力"不得记为"无回复"）
**根因教训：把已作答的必答题当成缺答，会系统性低估现状。** 澳门项目上一版报告即因
"只填了高校装机 + 把企业侧写成'未公开披露'"，把当前算力少算了一半以上。

1. **必答题必然有答案**：`survey_definition.json` 中 `required=true` 的字段，在
   `finished=True` 的完整提交里 **100% 有值**。先算"完整提交中该题的作答率"——
   若为 100%，就不允许在报告中写"无回复/未公开"。
2. **`0` 是有效答案**（＝无在用算力），**不是缺答**；`0` 与"空"必须分开统计与表述。
3. **"当前算力"必须从 q4 填充**，并按**两个口径分列，绝不混算**：
   - **口径A 本地装机**（自建／私有化部署，物理在澳）——由 q5「算力来源」判定；
   - **口径B 在用算力**（含租赁公有云）——q4 的原始含义。
   q5＝"以上都有"的混合型企业需说明"本地/云无法从本问卷拆分"，给出**下界**（纯自建之和）
   与**上界**（自建＋混合），不得取单一均值掩盖区间。
4. **q4 必须与 q6 交叉校验后才可采信或否定**：把 q6_detail 的"卡型×数量"按单卡/整机
   FP16 基准折成 P，与 q4 比对。
   - 比值落在 0.5—2.0× → **判为自洽，直接采用**；
   - 比值越界或卡型未识别 → 分条标 `【冲突】`/`【存疑】`，说明分歧点；
   - **禁止在未做逐条校验的情况下，把整批自报值判为"单位存疑"或"按卡数理解"**（这会
     误杀可信数据）。
5. **"当前算力"总口径必须分项拼装**，至少含：
   `企业（问卷 q4）＋ 高校与科研 ＋ 政务/社会资本（有公开者）`。
   **高校侧不在企业问卷内，必须单独并入**；未公开的分项记为负面发现，不得静默省略。
   每个分项标注**口径（本地装机/在用）、年份、折算基准**。
6. 硬件换算基准（单卡/整机 FP16 稠密算力）与 A100 等效折算系数，一并写进
   《附录·调研方法与口径说明》并注明来源（R6.1）。
7. **多份问卷 / 多轮回填必须分别处理，不得混算**：
   - **同一份问卷的多次导出**：以**最后一次导出**为准，并在正文标注导出日期（如"2026-09-30 导出"）；
     首轮结论若被新数据改变（如完成率、顾虑排序），**必须回头改正文**，不得让新旧数字并存；
   - **同一主体的多次提交**：按主体名去重——**优先 `finished=True`，其次取最新**（`--dedup`）；
     去重前后的两条合计都要报（"未去重 274 P／去重 250 P"），让读者看到差异；
   - **不同问卷（企业卷／高校卷／政务卷）**：**分项列示、口径互不替代、不得直接相加**；
     各卷的题号可能不同（企业卷总量题是 q4，高校卷是 q7；来源题 q5 vs q8），
     用 `parse_survey.py --total-qid/--source-qid/--detail-qid/--train-qid` 显式指定；
   - **样本量必须写明并警示外推**：n=1 的问卷（如高校卷仅 1 校回复）只能作为**个案一手证据**，
     正文须写"n=1，不可外推"。
8. **异常值单列（R6.3 护栏的问卷应用）**：自报值若出现"一家占合计过半"的极端值，
   **必须单列并给出含/不含该值的上下限**（澳门报告：HKBN JOS 澳门自报 115 P，占 21 家合计 57%，
   含之本地装机 160 P／不含 45 P），并说明该主体是否为集团级或跨境共享资源。
9. **"投入"与"需求声明"必须交叉检验**：若受访者申报的需求量级远高于其自报年度投入
   （澳门大学样例：年度投入 ≤10 万元 MOP，却申报 2027 年 >300 P），必须**并录并给政策含义**——
   这类需求是"能力愿望"而非"预算约束下的采购意向"，**公共平台按需求声明配置容量将系统性高估付费需求**。

### R10 算力指标必须逐值精确引用
适用范围：**任何算力指标数值**——`PFLOPS` / `P@FP16` / `Eops` / `EFLOPS` / `A100 等效` /
`卡时` / `加速卡张数` / `GPU 数` / `上架率·利用率` / `算力规模`（含"元/卡时"类单价）。

1. **贴到值上（精确到值，不是精确到行）**：角标必须紧贴该数值——同一段落内紧随数值之后，
   或**该数值所在的表格单元格之内**。
   **不得**只把角标挂在整行的"来源/备注"列、段末或章节末；那是"粗到行"的引用，
   读者无法判断这个数究竟出自哪一条。
2. **引到条（唯一定位"哪份文件的哪一处"）**：

   | 来源类型 | 条目必须写到 |
   |---|---|
   | 政府文件 / 法规 / 判给 | 机构 + 文件名 + **文号或批准文件号** + 日期 + 具体定位（第 X 条 / 表 X / 第 Y 页） |
   | 网页 / 新闻 | 标题 + 机构 + 发布日期 + **URL** + 抓取日期 |
   | 企业财报 / 招股书 | 报告名 + 报告期 + **页码或章节** |
   | 一手调研底稿 | 文件路径 + **记录级定位**（记录号 / 企业名 / 题号），如"问卷记录 #19，q4" |
   | 高校 / 平台公开资料 | 单位 + 资料名 + **具体规格表** + 抓取日期 |

3. **推算引输入**：标 `【推算】` 的算力指标，除公式与参数（R6.1）外，必须**逐个入参引用其来源**；
   不得只引"本报告推算"。
4. **禁止组引用兜底**：不得用 `[[74,75,77]]` 这类"调研报告整体"条目去支撑一个**具体算力数字**；
   若该数字确系该报告的原创推算，按第 3 条处理（给公式＋参数来源）。
5. **口径随值**：同一处出现两个口径不一的算力值（如 `4 Eops` 与 `1.16 EFLOPS`），
   必须**各自引用并注明口径**，不得合并成一个角标。

> 可机器校验的部分（Step 7）：**数值单元格的"自带角标率"必须为 100%**。
> 实测记录（澳门报告）：**改进前 34%**（122 个数值单元格里仅 41 个自带角标，66% 粗到行）
> → **改进后 180/180 = 100%**。工序：`add_table_citations.py` 先挂 → `move_citations_to_value.py` 落位
> → 对"按列分源"的表（如对标数据明细表的算力规模/电价/PUE 各来自不同文件）**人工按列拆引用**。


### R11 模型服务（MaaS）供应链安全（引用外部安全事件时的规范）
若报告涉及"用云 / 第三方模型服务 / 跨境推理"的可行性判断，**必须把供应链风险写成机制，而不是转述一条耸动新闻**：
1. **只提炼机制**：从事件中抽出**可执行的工程与合规事实**（如"第三方中转会静默留存对话并形成二次转售市场""ZDR 须在受控 VPC 隧道内实施才有效""供应商改为回复前摘要化推理以降低被窃转录的训练价值"），**不作政治判断、不作事实认定**；
2. **口径并录（R6）**：指控类事件必须标明**证据级别与是否为单方指控**，并**并列反方口径**（本例：Anthropic 单方指控 vs 中国政府否认"歪曲事实"）；
3. **精确引用（R10）**：引到**原始报告章节 + URL + 抓取日期**，媒体转引另列一条；
4. **落到采购条款**：每条机制必须转成**本报告对澳门公共算力平台的可执行建议**（受控通道、禁非受控中转、ZDR 可验证、不得留存 Prompt/输出用于训练、CoT 不外泄、供应商变更须提前告知）；
5. **与本地证据挂钩**：尽量与本地一手证据串联（如问卷中"云服务/AI 模型是否构成境外接收方"的堵点）。

### R12 走访纪要与一手访谈作为证据源
面对面走访纪要（截图/表格/速记）是**一手证据**，但形态最脆弱，必须按以下纪律使用：
1. **记录级定位（R10）**：引用时写明**来源文件 + 企业名 + 字段名 + 日期**；若原件为截图，**必须声明其为截图/局部视图**（如"行号显示为 1/2/9/10/11/12/14，属被筛选的局部视图"）；
2. **量纲待核**：纪要中的**数量、单位、口径**（P 是 FP16 还是定点？卡数是"张"还是"台"？）若原文未注明，一律标 `【待核】`，**不得直接进入量化结论**；
3. **与桌面口径冲突时并录（R6/R6.5）**：一手走访与企业公告、项目介绍、报告模型不一致时，**逐条并列并说明差异成因**；"以官方口径为准"仅适用于**官方 vs 非官方**，**不适用于"企业自述 vs 桌面推断"**——后者须保留两方数值；
4. **优先提取"企业亲述的取舍"**：如"因成本太高导致训练未成功""因 Token 成本战略放弃微调"——这类自述是**结论的最强引证**，价值高于任何推算；
5. **不得用截图里的数字替换既有结构化数据**，除非完成第 2 条的核对。

### R13 报告骨架与附件范式（政府/产业研究报告体例）
参照《四川省算力发展研究报告》（华为，2026-02）等成熟政府侧报告，本 skill 采用如下体例要求：

1. **摘要 = "针对 N 个核心问题逐条作答 + 章节指向"**。不要写成泛泛的背景复述。每条格式：
   `N．<主题>：第 X 章（Y）小节。` + **一句话结论（带数字）**。四川报告即围绕"发改委提出的七大核心问题"逐条作答（需求／产业／布局／异构／算电／调度／政策）。
2. **"问题"章与"措施"章必须一一对应**。四川：三章列 6 条问题（统筹机制／电算布局／调度体系／供需关系／产业带动／政策支持），五章按 5 个"协同"给措施。**问题清单与措施清单要能逐条挂接**（与 R8 映射表是同一件事）。
3. **措施章按"协同维度"组织**，基线五维：**产业协同 / 布局协同 / 技术协同 / 算电协同 / 政策协同**。
   - **"算电协同"是必选项**（国家层面 2026 年 3 月首次写入政府工作报告；四川专设一节并做成政策建议专件）。澳门侧证据充分：**PUE 零公开、输入型电力系统（购自内地 87%）、大型算力中心"预计将消耗大量电力资源"**——缺此节属结构性缺失。
   - **技术协同要给可执行原则**，如四川的"**单一集群内同构，跨集群异构协同**"（训练优选同构、推理分层异构），并**严格区分训练与推理**两类场景。
   - **政策协同要落到机构**：四川建议设"省人工智能发展与算力建设运行专班"。澳门对应应给出**"单一窗口/专班"式跨部门协调机制**——本报告已有硬证据（走访中易研明确担心"经科局与公职局之间的部门墙"）。
4. **需求测算必须设"估算说明"专件（附录）**，顺序固定：
   `国家基线（精度口径 FP16/FP32/FP64 分列）→ 本地现状与占全国/占枢纽比例 → 供给侧（多家机构增长率交叉）→ 需求侧（行业标杆值 + 龙头企业调研 + 企业数量×渗透率）→ 分行业拆分（智算/通算/超算分列）→ 口径警示`。
   这是 R6.1"推算三件套"在附录层级的展开；**精度口径必须分列，不得混算**。
5. **企业调研附录用"五段式企业档案"**（四川 10 家企业统一体例，可直接照搬）：
   ① 企业基本情况（营收/规模/行业地位/数字化基础）→ ② AI 重点应用场景及发展阶段 → ③ **当前 AI 算力使用情况（本地/云、通算/智算/超算、具体卡数与 PFLOPS）** → ④ **"十五五"算力需求预估（驱动因素 + 总量倍数 + 分年度规划 + 自建与云租比例）** → ⑤ **发展痛点和政策诉求（分条、可直接转化为政策建议）**。
   **每个产业/行业再收一段"总结和分析"**，形成"逐家档案 + 产业小结"两级结构。


### R14 端到端最终态：报告是成果，不是工作日志

**用户明确要求**："这是一份端到端报告，应该直接呈现最终结果，而不是以增量形式记录所有过程。"
新数据到达时，**必须回头改写原有判断**，而不是在旧判断旁边追加"新增／补充／更新"段落。

1. **禁止过程痕迹**。全文不得出现：`第一轮/第二轮/首轮/本轮`（指数据轮次时）、`回填`、`数据版本`、
   `较首次`、`此前被系统性低估`、`应修正为`、`待核/待补证事项`（作为任务时）、`新增 N 份`、
   `最新导出为准`。→ **一律改写成最终口径的陈述句。**
   （例外：`本轮国家战略`、`双轮驱动`、`新一轮产业竞争`、`轮换账号` 等属正当用法，需人工判断。）
2. **同一事实只留一个版本**。新旧数据冲突时，正文只呈现**最终口径**；
   确需说明差异时，改写成**实质性口径警示**，而不是数据版本说明。
   - ❌ "首轮因单位存疑被搁置，本轮经换算后判定自洽"
   - ✅ "q4 自报值经与硬件明细逐条换算后判定自洽，故予采用"
   - ❌ "问卷第二轮回填后，21 家自报合计 202 P"
   - ✅ "21 家澳门有效主体自报在用算力合计 202 P"
3. **判断要跟着数据改**。若新数据推翻原有结论句（如"澳门科技企业普遍没有任何算力披露"），
   **必须重写该结论句本身**，并在同一处给出新的、更准确的结构性判断
   （例：改为"披露意愿的两极分化——头部不愿披露、中小愿意报数；以公开披露为口径统计会系统性低估"）。
4. **内部规则编号不得出现在正文**。`R6`/`R10`/`R12` 等是本 skill 的内部编号，读者无从理解；
   必须转成方法论表述或限制声明（如"按 R6 须并录" → "两者统计对象不同，故并列呈现而不相互否定"；
   "按 R10 不得混用" → "两套口径不可比，本报告量化结论采用后者"）。
5. **交付前自检**（Step 7 已内置）：对过程词表做全文 grep，**命中应为 0**（正当用法除外）。

### R15 附录正文单倍行距 + 文件名用当天 CST 日期

**用户明确要求**："所有附錄的内容使用单倍行距（标题除外），文件名使用当天CST（+8）时间。"

1. **附录正文一律单倍行距**。自 `附錄A`（简体 `附录A`）起至文末，**所有正文块**——表格单元格、
   列表项、引文块（`>`）、参考文献 `Rn.` 条目、图表题注——一律 `w:line="240" w:lineRule="auto"`；
   **标题（章 / 节 / 子标题，含 `附錄A` 与 `【一】` 分组标题）保持版式档原行距**
   （gov 档 = 360 / 1.5 倍）。"标题除外"是用户明确给出的例外，不得顺手一起压掉。
2. **必须同时关闭网格吸附，否则改动等于没做**。gov 档页面带
   `w:docGrid w:type="lines" w:linePitch="360"`；只要 `w:snapToGrid` 取默认值 true，
   Word 会把每个文本行**吸附回网格行高 360**——单倍行距（240）与 1.5 倍（360）**视觉上完全一致**。
   故附录正文段落必须显式写 `<w:snapToGrid w:val="0"/>`。
   ⚠️ 该元素必须插在 `w:spacing` **之前**（OOXML `pPr` 子元素有固定次序，乱序 Word 视为非法文档）：
   用 `pPr.insert_element_before(el, 'w:spacing', 'w:ind', …, 'w:pPrChange')`，**不能 `append`**。
3. **实现已内置于 `assets/md2docx.py`**，不要手改 docx：
   - 主循环遇到 `^附\s*[錄录]\s*[A-Z]` 的标题即置 `IN_APPENDIX = True`；
   - `appendix_line(p, line)`：附录内返回 `1.0` 并写 `snapToGrid=0`，否则原样返回；
   - 全部正文构造函数（`add_body` / `add_list_item` / `add_table` 的单元格与表后空段 /
     `add_quote` / 题注 / 参考文献条目 / 图片段）都经 `appendix_line`；
     **`add_heading` 不调用它** → 标题行距天然不受影响。
4. **文件名日期**：交付文件名一律用**生成当天的 CST（UTC+8）日期**，即 `<报告名><YYYYMMDD>.docx`，
   由 `"…$(TZ=Asia/Shanghai date +%Y%m%d).docx"` 生成——**不得沿用旧日期、不得手写**。
   被取代的同名旧版本应删除，避免两份"最终版"并存。
   （注：文内"编制/报告日期"属**内容**，不随文件名自动变；若需同步须先问用户，不要自行改。）
5. **验收**（Step 7 已内置）：附录区**非标题段落 `w:line` 全部 = 240**、
   **标题 `w:line` 全部 = 360**、**`pPr` 子元素乱序段落数 = 0**。

### R16 终态报告不得设"稻草人"（不得反驳读者从未见到的判断）

**用户明确要求**："重新理顺全篇逻辑，在输出终态报告的情况下……'澳門企業沒有算力'的判断似乎不应该出现？"

终态报告只呈现**调查得出的结论**。一旦把结论写成一个**被否定的命题**
（`"X"并不成立`、`"X"这一推断不成立`、`澳门并非没有算力，而是…`），而该命题
**从未作为本报告或某一具名外部主体的观点出现过**，读者会读成"作者在跟自己先前的稿子辩论"——
这是工作过程的残留（R14 的姊妹缺陷），必须改写为**正面陈述**。

1. **判定标准（三问）**——被否定的命题，来源是哪一个？
   - ① **本报告已列出的外部主张**（具名/可溯源，如"坊间常引第16条""政策文件称横琴营运成本低于澳门"）
     → **可以保留**对照；
   - ② **同一段落并列展示的两份文档事实之间的表面张力**（如"全球第七固网速度"与"国际带宽匮乏"）
     → **可以保留**辨析；
   - ③ 以上都不是 → **稻草人，必须改写**。
2. **改写手法：删掉否定式，直接给判断。**
   - ❌ `**（二）但"澳门企业没有算力"并不成立**——问卷显示…`
   - ✅ `**（二）企业侧存在一份公开披露无法覆盖的算力存量**——问卷显示…`
   - ❌ `**因此"澳门没有算力"并不成立；准确的表述是"澳门没有公共的、可被企业调用的算力"**`
   - ✅ `**准确的结构性判断是：澳门真正缺的是"公共的、可被企业调用的算力"**`
   - ❌ `"国家信息中心未就澳门算力做过测算"这一推断不成立` ／ `上述负面发现依然成立`
   - ✅ 直接写第三条线索本身，并注明与上一条线索**分属不同议题、两者不可互为佐证**
3. **不得用"过程叙事"承载口径更正**：`补充检索结果（日期）`、`前述检索所指`、
   `本次调研最重要的负面发现`、`走访带来的增量判断`、`（新增）`、`此前未见…`
   ——一律改为**事实陈述**：`公开信息缺口`、`三点判断`、`尚未公开的关键信息`。
4. **"负面发现"要译成读者的语言**：读者要的是"这项信息公开不公开"，不是"我们检索到了什么"。
   - `本次调研确认的负面发现包括` → `已确认的**公开信息缺口**包括`
   - `（核心负面发现）` → `（**不存在任何公开数字**）`
   - 例外：作为**证据分级**声明时（"已穷尽检索并确认无此公开统计"）**保留检索范围与结论**，
     只是不再自称"发现"。
5. **自检**（Step 7 已内置）：交付前 grep
   `并不成立|不成立|并非没有|负面发现|走访前|补充检索|增量判断|待补证|（新增）`，**命中应为 0**。

## 四、常见失败模式（真实踩过的坑）

| 失败现象 | 根因 | 规避 |
|---|---|---|
| **Word 打开后全文档跨标题连续编号** | 用了 `List Number`/`List Bullet` 样式或 `<w:numPr>` | 见 R2：字面量编号 + 普通段落 |
| **`[1,2,5]` 点哪个数字都只跳到 [1]** | 整串被当成**一个** hyperlink | 用 `add_citation()`：逐编号建链，`,` `[` `]` 为普通上标 |
| **附录分组标签不在导航窗格标题树里** | 用 `**加粗正文**` 冒充分组标题 | 写成 `#### 【一】…`（→ outlineLvl 3），并让其父级为 `### 附录X` |
