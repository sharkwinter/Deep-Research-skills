# Survey Analysis Notebook - 问卷数据分析 notebook

## 触发方式

`/survey-analysis-notebook [问卷项目目录或说明]`

例：`/survey-analysis-notebook /root/Working/polling/polls/macao`

## 适用 / 不适用

| 场景 | 用哪个 skill |
|---|---|
| **已有线上问卷，要用答卷做量化分析并产出 notebook** | **本 skill** |
| 把 xlsx/docx 问卷建成线上问卷、改题后同步 | `/xlsx-to-survey` |
| 把纸质/扫描 PDF 回填成线上问卷的一份答卷 | `/survey-backfill` |
| 把调研结论写成正式 Word 报告 | `/docx-report` |

本 skill 的产出是**可执行、可复现、可增量更新**的 `.ipynb`，不是一次性报告。

## 前置条件（先确认，缺一项就停下来问）

1. **问卷 id**：每份问卷一个（Formbricks `surveyId`）。多份问卷（如企业卷／高校卷）分别列出。
2. **API Key**：Formbricks Management API 的 `x-api-key`；不同 workspace 的问卷可能要**不同的 key**。
3. **取数地址**：在 **Jupyter 容器内**取数时不要用宿主公网 IP／域名——容器访问宿主公网 IP 会超时（hairpin NAT），
   要用 compose 服务名：`http://caddy`（Caddy 反代）或 `http://formbricks:3000`。
4. **Jupyter 环境**：目标容器名、`--notebook-dir`、访问 URL 与 token；容器内是否已挂载工作卷。
5. **中文字体**：容器若没有 CJK 字体，图表中文会变方块。随卷携带字体文件并在 notebook 里 `font_manager.addfont`。
   本机没有 sans CJK 时用 `wqy-zenhei.ttc`（16 MB）即可。
6. **是否已有「已发布口径」**：若此前有对外发布过的数字（报告/PPT），必须拿到**逐主体**口径表，
   用来做「最新 vs 已发布」对照；没有的话也要在 notebook 里明确写"本版为首次口径"。
7. **LLM（可选）**：若要归类自填文本，确认网关地址/模型/Key 可用；**推理模型要留足 `max_tokens`**。

## 执行流程

### S0 侦察（不要跳过）

- 拉一次全量答卷，打印：记录数、`finished` 数、时间跨度、每列的非空数。
- 拉问卷定义（`/api/v1/management/surveys/{id}`），把**题号 → 题干**落成对照表；
  找出四类关键题的题号：总量题（如"当前算力多少 P"）、缺口题、未来 1 年/3 年题、构成题（来源/场景/意愿）。
- 统计每个关键列的**作答形态**：纯数字？区间选项？自由文本？各占多少条。
  → 这决定后面用点值口径还是区间口径。
- 找出**格式问题**：多选值是不是 list、含不含"其他"自填文本、繁简/全半角混用、分隔符是否规范、
  有没有测试记录（`test`、`1`、`test123`）与非本地主体。
- 若已有已发布口径表，**逐项复算**它（中值、合计），确认自己能复现——复现不了就先弄清口径，不要动笔。

### S1 写 `build_snapshot.py`（先有数据层，再谈 notebook）

输入线上 API，输出**逐主体快照 JSON**，字段至少包含：
`name / cur / gap / y27 / y29` ＋ `y27_lo/mid/hi`、`y27_open`、`y29_open`、`y27_未答` 等；
高校类问卷还要 `type`（科研型/教学型）、原始作答文本 `*_raw`、硬件明细、备注。

必须实现的规则见下节「口径规则（硬约束）」。

**自检**：脚本结束时打印三档合计与样本数；若项目有已发布数字，在旁边打印出来做对照。

### S2 搭 notebook 骨架（数据层 + 实时层）

- **数据层（第一部分的事实来源）**：加载最新快照 JSON。**优先读卷内文件、回退内置副本**——
  这样更新数据只要换卷内文件，不必重建 notebook。
  同时加载**已发布口径**快照，用于对照。
- **实时层（第二/三部分的分布剖析）**：每次运行直接打 API，保证分布、交叉分析、自填文本都是最新的。
- 把两个数据层的角色写进 markdown，避免读者混淆"哪个数才是要引用的"。

### S3 第一部分：核心估算（放在最前）

按用户关心的 3—5 个指标（如 当前值 / 近期缺口 / 未来 1 年 / 未来 3 年）给出：
1. **分档表**：口径分档（主口径／下限／参照）× 指标列，并给出倍数（如 2029÷在用）。
2. **已发布口径对照表** ＋ 差异列。
3. **逐主体差异表**：新增／消失／回改，差额必须能逐条解释。
4. **逐主体原始表**（可自由 print 的 DataFrame）。
5. **下限／中值／上限三套 DataFrame** ＋ 汇总三值表。
6. 图：① 包线＋中值（横向）；② 年度轨迹包线（中值折线 + `fill_between`）；③ 逐主体区间包线。

### S4 第二部分：汇总数据

样本漏斗（记录数→具名→有效→提供关键题）、提交时间线、关键题分布（分档/来源/构成/意愿/价格/机房）。
每个分布都要**分母**（"占 N 家有效样本"）。

### S5 第三部分：深入剖析

按角度成节，每节"表 + 图 + 结论句"：存量结构（集中度 CR1/CR3/CR5 与量级护栏）、
缺口与增长、样本质量与护栏（重复提交、量级差、矛盾作答）、双中心/部署偏好、
合规与跨境、意愿×价格×缺口、专项章节（如高校逐校）、供需汇总与政策含义。

### S6 自填文本 LLM 归类（多选题的"其他"）

单独一节：格式问题诊断 → 待归类清单 → LLM 多标签归类（**封闭类别集**）→ 人工复核 → 统计与图表 → 逐条明细。
细节见「口径规则」与「坑清单」。

### S7 在容器内执行验证

```bash
docker cp <nb>.ipynb <container>:/home/jovyan/work/
docker exec -u root <container> chown jovyan:jovyan /home/jovyan/work/<nb>.ipynb   # 否则 jovyan 无法保存
docker exec <container> bash -lc 'cd /home/jovyan/work && jupyter nbconvert \
  --to notebook --execute --inplace --ExecutePreprocessor.timeout=900 <nb>.ipynb'
```
- 出错时先用 `--allow-errors` **一次性收集全部错误**再统一修，比逐个报错快得多。
- 执行后用脚本扫 `outputs` 里的 `output_type=="error"`，必须为 0。
- 抽查关键数字与已发布口径的一致性；抽查图片是否真的画出来（`image/png` 计数）。

### S8 落地与文档

- 把执行过的 `.ipynb` 拷回工作区存档（交付件含输出）。
- `README.md` 写：访问 URL/token、目录结构、口径、**数据更新三步**、已知坑。
- 若要长期维护，把本 skill 的「更新流程」抄进 README。

### S9 讲清"哪些数能对外引用"

在 notebook 开头就写明：**已发布口径**（对外引用）／**最新快照**（内部更新）／**实时层**（分布剖析）三者的关系。
读者最容易犯的错是把"实时层未做人工校订的口径"当成对外数字。

## 口径规则（硬约束）

### 1. 区间三值换算（唯一约定）

| 作答形态 | 下限 | 中值 | 上限 |
|---|---|---|---|
| 区间 `a–b` | a | (a+b)/2 | b |
| 开口下界 `<N`／`小於N`／`N 以下` | 0 | N/2 | N |
| 开口上界 `>N`／`N 以上` | N | N | **开口（不设值）** |
| 点值（如 `1500`） | 值 | 值 | 值 |

- 解析前**必须剥离精度标记**（`P@FP16`／`FP16`／`P@FP32`）——否则其中的 `16` 会被当成区间端点
  （实测把 `60+ P@FP16` 解析成 `(16, 38, 60)`）。
- 开口项**不参与上限加总**：表内写 `NaN` 并在表下注明"上限不可加总（实为 ≥ 下限合计）"，图内画箭头。
- 但同时给出**「上限封顶」对照口径**（`tier_bounds(..., cap_open=True)` → `TIER_BOUNDS_CAP`）：
  把 `>P` 按 P 计入、与其余主体的有限上限相加，得到**可加总**的保守上限。
  用户若要求"图上要给一个具体上限"，就用封顶值画实线并在图内加注：
  `<上标号> <档位>：<企业名> <年> 上限申报「>500P」，记为 500P，与其他上限值累加`。
  **标号用 ①②③（U+2460…，WQY Zen Hei 有字形），不要用 `＊`**——`＊` 无法区分多条注记；
  一次换算挂一个号、接在上限值后面（`6,450 ①`），同一次换算的多档共用同一个号，按出现顺序自上而下编号。
  注记画在坐标区**下方**（`fig.text` ＋ 抬高 `ax` 位置），不要放在坐标区右上角——长注记会压住前几行的包线。
  **哪几年封顶要问清**：开口可能同时出现在 2027 与 2029（如参照档的极视角 `>300P`／`>500P`），
  用户只说 2029 时先按 2029 做，随后往往会要求 2027 也照办。
  表与已发布数字仍保留原始开口口径，**只在需要可加总的那张图**上用封顶值，并在正文说明差异。
- **「未作答（—）」与「开口」都是空值，必须分开标记**（`*_open` / `*_未答`），
  否则会把未作答误报成"开口、上限不可加总"。

### 2. 样本筛查与归一

- 剔除：测试/占位符（`test`、纯数字、长度 < 4）、非本地主体（维护一份显式名单，不要靠猜）。
- 主体名归一：`NFKC → 繁转简 → 去空格 → 去后缀`（有限公司/股份有限公司/（澳門）…）。
- 别名合并：**包含式（长度 ≥3）＋共同前缀（≥6 字，覆盖中英两式）**，
  但必须用**并查集**求连通分量取代表——朴素 `next(...)` 会出现 A↔B 互指，同一实体留两条。
- 同一主体多份提交：取「**作答字段最多、其次最新**」的一条，并在明细表留档其余提交。
  若两份提交是**不同层级**（学校本体 vs 下属研究院／学院），另按坑清单 #16：以「最新、层级更高的整体填报」为准，
  且所有按主体计数的图都要改走去重后的那份数据。
- **三个基数不得混用**：记录数 ／ 具名主体 ／ 提供关键题的有效样本。

### 3. 口径分档（有异常值时）

- `主口径`＝剔除量级异常主体（T11：单主体占合计 ≥50% 且与本人其他作答矛盾）。
- `下限`＝再剔"另给下限"主体（T1：单主体占同类合计 ≥30%）。
- `参照`＝全部样本，**只用于展示越界值影响，不作为规划依据**。
- 每个"剔除/另给下限"都要写**三条理由**（提交矛盾、缺口大于自报未来总规模、硬件与投入为 0 之类）。

### 4. 已发布口径 vs 最新快照

- 一旦某版数字对外发布过，就把那份**逐主体表**冻结存档（`macao_frozen_<日期>.json`），永不覆盖。
- 新快照与它做**两层对照**：指标级（差额列）＋逐主体级（新增／消失／回改）。
- 差额必须能解释为"新增作答 + 既有主体回改"；解释不了就先查口径，不要发布。

## 图表约定

- **matplotlib**，不用 plotly（容器常无 kaleido，且 plotly 需 Lab 扩展才能渲染）。
- `figure.dpi = savefig.dpi = 200`（110 会发虚）。
- 中文：随卷携带 `wqy-zenhei.ttc` → `font_manager.addfont()` + `plt.rcParams["font.sans-serif"]`。
- **有序类别自动排序**：把标签解析成 `(下界, 上界)` 升序——
  `0 P → <10 P → 10—49 P → ≥50 P`；`小於10P → 10–30P → … → >300P`；
  `＜30% → 30%–70% → 70%–90% → ＞90%`；`沒有 → 10 櫃以內 → 10–30 櫃 → …`。
  无法解析的（未填／其他／文字类）置末尾按家数降序；**多选题、名义题保持家数降序**。
- **包线图**：粗半透明线＝下限—上限，圆点＝中值，两端标数值；
  点值行只画一个点并标"（点值）"。
- **开口（`>P`）怎么画——两图必须同口径**：若业务上需要"一个能加总、能比较的上限"，就统一用
  **封顶值**（见上文 `TIER_BOUNDS_CAP`）画实线，绝不让一张图封顶、另一张图还画"開口（不設上限）"箭头
  （用户会立刻发现口径打架）。**换口径时要全篇扫一遍旧措辞**：`開口`／`不設上限`／`未封顶`／
  "兩圖口徑不同"之类的句子，以及硬编码的 `48 家`／`三校`／`n=3`——这些最容易留在正文里变成自相矛盾。
- **标号 + 图注共享**：把 ①②③…（U+2460…，WQY Zen Hei 有字形）与注记文本在**汇总 cell 里一次算好**
  （`CAP_MARK[(口径, 指标)]` / `CAP_FOOT` / `CAP_NOTE`），所有图共用同一套编号；编号按主图的**行序自上而下**，
  同一次换算的多个口径档**共用一个号**（否则读者对不上号）。图注用公共函数画在坐标区**下方**：
  ```python
  def _fig_note(fig, ax, lines, fontsize=7.8):
      need = 0.175 * len(lines) / fig.get_figheight()
      p = ax.get_position(); ax.set_position([p.x0, p.y0 + need, p.width, p.height - need])
      fig.text(0.012, 0.012, "\n".join(lines), ha="left", va="bottom", fontsize=fontsize,
               color="#3f3f46", linespacing=1.6)
  ```
  放在坐标区右上角会被长注记压住前几行——别这么干。
- **标注防裁切**：靠右的点标注在左侧、靠顶的点标注在下方，并给 `ax.margins(x=…, y=…)`。
- **需求轨迹图：每张图只画「该问卷的一组口径」**（用户实测指正「企业问卷需求轨迹有重复」）：
  - 四点一律用**水平值**：`當前在用 → 2026 年底需求（＝在用＋缺口）→ 未来 1 年需求 → 未来 3 年需求`。
    **不要把「缺口」（增量）与「需求总量」（水平值）当成相邻两点**，也不要让总览图与包线图各画一遍。
  - 同一张图里**一个问卷只画一条线**：`下限档`（再剔若干主体）是敏感性口径，只放在专门的包线图与三档汇总表，
    不要在总览图里与主口径并排再画一遍（读者会立刻说"重复"）。
  - 缺口若要在图上出现，就画在 `在用＋缺口` 那根柱**内部**（白线分段＋「缺口 N」），而不是另立一根柱。
  - 顺带做一次**口径自洽校验**：`在用＋缺口 > 未来 1 年需求声明` 的主体逐一列名——这类自报前后不一致
    应写进护栏、留待走访核实，不可作规划输入（本项目高校 1/4 校、企业主口径 7/50 家命中）。
- **另一份问卷的同类数据要"参照"主问卷的画法**：给新主体（另一所学校／分行／试点城市）单独出一张**同画法**的图，
  并把主问卷的中值曲线作为**参照线**画在同一坐标里、逐点标注「新/主 = x%」——
  比把两者塞进同一张图里更好读，也直接回答了"参照着画"这类要求。
- 每张图下面写一句"読圖/说明"，把口径讲清楚（是点值还是区间、分母是谁、**有没有封顶**）。
- **多选题的"份额"与"普及率"是两个数，都要给，且别混读**：
  份额＝该选项勾选数 ÷ 全部勾选数（会重复计人，头部两三项合计往往才 1/3，看着很"分散"）；
  普及率＝勾选该选项的主体数 ÷ 该侧有作答主体数（"44/55 家＝80% 在用 DeepSeek"）。
  读者（和领导）几乎必然把份额读成"多少比例的单位在用"，所以份额饼图旁边另出一张按主体的普及率表，
  并在图注/结论里写明两者分母不同。饼图结论还应给出 CR1/CR3/CR5、国产／海外／自研分组、
  以及"某侧只有 N 个单位 ⇒ 1 次勾选＝x pp、1 个单位＝y pp"的粒度护栏，防止把一两次勾选的抖动读成偏好差异。
- **计数不要写死**：`{len(df)} 家`／`{len(UNIV_F)} 校`／`n={len(UNIV_F)}` 用 f-string；样本一变（新增主体、
  新增一所学校）写死的 "49 家／三校／n=3" 会立刻与表里的数字打架——这类残留最好在交付前 grep 一遍。
- **合并宽表（跨问卷汇总用）**：企业＋高校的行合在一起时，
  - 行索引两级 `(類型, 主體)`（方便 `df.loc["高校"]`），列索引两级 `(年份, 下限/中值/上限)`；
  - 把"分量列"（如 `在用`／`缺口`）留在**最前面**作为参考组 `("參考", "在用")`，再给合并列（如 `2026 = 在用＋缺口`），
    读者才能自己验算；参考列**照实留空**（不按 0 填），合并列才按约定把未作答记 0；
  - 开口项在"上限"列仍留空（不可加总），用快照的 `*_open` 标记判断（**不能用 `isna()`**——
    开口与未作答在数值上都是空）；
  - 另出一张 `groupby(level="類型").sum()` ＋ 合计行的对照表，让合并列的合计能对上汇总表。

## LLM 归类自填文本（多选题"其他"）

1. **先做格式诊断表**：其他项无标记／多条并列分隔符不规范／繁简混用／超长粘贴／无意义占位符——
   每类给命中数、说明、处置。
2. **判标准选项**：`NFKC → 去括号 → 繁转简` 后与标准选项**去括号的短名**精确比对（不要用子串匹配，
   否则整段粘贴的产品说明会被误判成标准选项）。
3. **余下交 LLM**，提示词要求：
   - **封闭类别集**（N 个标准类别 + M 个补充类别 + 「無效作答」），**不许自创新名称**；
   - 可多标签（一条含多个场景就给多个）；
   - 超长粘贴只给最核心 1—2 类，避免单条贡献 5 个类别；
   - 严格输出 JSON（键为原值逐字复制）。
4. **缓存**：结果写卷内 `.cache/*.json`；有缓存就不重复调用。分类名做**别名归一**兜底。
5. **失败回退**：调用失败/超时 → 用人工复核过的**冻结映射**，并在输出里说明"本次回退，结果不受影响"。
6. **人工复核**：对个别条目按规则覆盖，表里同时留"LLM 原始类别 / 复核后 / 是否调整 / 理由"。
7. **统计与图表**：归类后分布（完成样本 + 全部作答两张）、标准选项口径 × 归类后口径对照（含增量）、逐条明细。

## 问卷 × 深研档案 的联合筛选（榜单类交付：如「TOP 5 潜力企业」）

问卷给的是**单点自报**（未经稽核、覆盖广），调研档案给的是**带证据分级的事实**（覆盖窄、可信度高）。
把两者合起来出榜单时，纪律比模型重要：

1. **两层的认识论不同，必须分列**：同一主体同时给「问卷自报值」「深研自下而上估算」「折算量（卡数/卡时）」三列，
   并逐家写出背离原因。本项目实测：某芯片企业问卷 2029 报 1,500 P，而深研三情境最高只到 500–1,000 PFLOPS；
   某营销公司问卷 75 P，深研估算是 3.7–10.9 PFLOPS（差 7–20 倍）。→ **自报值不得直接当规划输入**。
2. **能力分层只认证据，不认头衔**：AI 兑现度按「在售产品/官方付费合同 ＞ 有第三方或官方佐证的落地案例 ＞
   只有叙事 ＞ 无」分层；**认证等级/资质不是能力代理指标**——本项目里最高等级的重点型有 L4（完全无 AI），
   而潜力型里有 L1。官网有 AI 页面 ≠ 有 AI 落地。
3. **未查 ≠ 无潜力**：没有深研档案的主体**不打分、不进榜**，另列「补研名单」并附问卷侧信号
   （算力、自研标记、投入）。把未知记成中性分等于把「不知道」写成「一般」。
4. **政策对齐要落到产业框架的每一条**，并**报告覆盖缺口**：本项目 TOP 5 里 4 家集中在「高新技术」，
   「1」旅游休闲、现代金融、中医药大健康在 AI 侧无同强度标的——这个缺口本身就是下一轮调研议程。
5. **加权评分要写死权重、留敏感性**：`_SC` 一个列表承载全部评分与依据（改评分只改这一处）；
   当第 5 名与第 6 名差 <0.15 分时，明说「并列候选」，不要让排名看起来比证据更确定。
6. **风险单列不摊平**：认证到期、财务脆弱、政策性归零（如政策把手续费/中间环节取消）、客户集中、数据合规，
   逐家写明并给**具体日期**；这类信息对决策者的价值常高于分数。

## 实测坑清单（都踩过）

1. **API 分页**：Management API `limit` 单页至多 50 且**不返回 `nextCursor`**；只取首页会静默丢样本。
   必须 `skip` 翻页。（旧 notebook 因此少算 12 条。）
2. **题目标签端点是 v1**：`/api/v1/management/surveys/{id}`；v2 同名路径 404。题干含 HTML，要剥标签。
3. **作答值是标签文本**：单选/多选返回选项**文本**而非选项 id；选了"其他"的行**不含选项标记**，只留自填文本。
   多选题的值是 **Python list**（如 `['DeepSeek', 'Qwen（通義千問）', '業務未上線']`）。
   **别把 list 先 `astype(str)` 再按逗号切**——那会得到 `"['DeepSeek'"`、`"'Qwen（…）'"` 这种碎片，
   图表标签全废（本项目 `multi_dist` 就中过此坑，2.5／2.6／3.5／3.7 的多选图标签残缺）。
   统一走一个 `as_items(v)`：list → 直接用；字符串字面量 → `ast.literal_eval`；
   分隔符拼接 → 按 `;；,，` 切。**单选题不要用它**（正文里的逗号会被切开）。
   另注：list 里可能混入 `""` 与自由说明（如"都想用（原表未逐一勾選…）"），要按规则剔除并**打印剔除清单**。
4. **hairpin NAT**：容器内访问宿主公网 IP／域名会超时，用 compose 服务名。
5. **pandas 3 的字符串 NA**：`astype(str)` 保留 NA，`.str.match()` 会给出 NA，
   布尔掩码含 NA 就不能用于 `df[mask]`。先 `fillna("")` 或 `dropna()`。
6. **`NaN` 不是 `None`**：从 DataFrame 取出空值是 `NaN`，判空要用 `pd.isna()`；
   写成 `x is None` 会让"开口"分支永不触发（图里少了箭头）。
7. **推理模型的 `max_tokens`**：`completion_tokens_details.reasoning_tokens` 会吃掉预算，
   给小了会返回**空 content**。留足（本项目 16000），并把 `finish_reason` 打进错误信息。
8. **`response_format={"type":"json_object"}` 可能不被网关支持**：首次失败后去掉它重试一次即可。
9. **容器常无 opencc**：繁简转换要有**内置回退字表**，且字表要按本项目**全部问卷文本**生成，
   否则标准选项匹配率会掉到个位数（实测 9.3%，225 条被误判）。
10. **build_notebook.py 的 cell 拼接**：用 `code(r'''…''')` 包 cell 时，替换 cell 要保留收尾的 `''')`
    —— 少的那个 `)` 会造成"invalid syntax / forgot a comma"，且报错行指向下一个 cell，很难找。
11. **nbformat 校验警告**：cell 加 `"id": f"cell-{i:03d}"` 可消掉 MissingIDFieldWarning。
12. **写宿主卷需要提权**：`/var/lib/docker/volumes/...` 不在会话工作区内，
    优先用 `docker cp` 进容器再 `chown jovyan`。
13. **两份问卷"题型不对等"时的合并**（如企业卷无品牌选择题、只有自填型号；高校卷有结构化多选）：
    - 先把两侧各自归一成同一套类别（自填文本 → 关键词规则；多选 → 逐项匹配），再合并；
    - **人工整理过的 detail 文本不能做关键词扫描**：本项目的 q9_detail 形如
      「NVIDIA：H100 ×2…。其他品牌：Apple M2…**HUAWEI（華為）欄未填**；H20／H200／T4 **未填**」，
      整段扫描会把"未填"当成"有填"（实测误判出華為与 NVIDIA 两个不存在的品牌）——
      有结构化字段就只认结构化字段，detail 仅作剔除理由的注脚；
    - 条件题（"如有自建算力…"）**无自建者不作答**，这类 `NaN` 行不能 `dropna` 掉，
      要留在剔除表里说明；反之"可选题"没填的行不要逐条列（几十行噪声），覆盖率先写清楚；
    - 表里同时给"提及数"（互斥可加总）与"主体家数／校数"（按主体去重，合計行取去重值），
      图注必须写明**覆盖率**（如 55 家完成企业中 34 家填答、26 家可识别品牌），
      并声明该图只代表"已披露硬件"的品牌结构。
14. **从自填文本里数"数量"（算力卡张数／机柜数…）：先屏蔽型号 token，再找数量**。
    型号名里全是数字（`H100`／`L40`／`RTX4090`／`A6000`／`800T`），直接跑
    `(\d+)\s*[*x×]\s*(\d+)` 这类模式会把「H100×8張」读成 **100 张**、「L40*16」读成 **40 张**（实测踩过）。
    做法：① 先用 `rtx\s*pro\s*\d{4,5}`／`rtx\s*\d{4}[a-z]?`／`\b[ahvlpb]\d{2,4}\b`／`\b(m[2-5])\b` 等
    把型号替换成 `<M>`；② 再按**优先级**取第一个命中的模式：`N*型号` → `型号*N` → `型号xN` →
    `N张｜N卡｜中文数字＋卡` → 尾随数字（`型号 8`）；③ 注意 `X` 不能全局替换成 `*`（`RTX4090`→`RT*4090`
    会凭空多出 4090），只在 `(?<=\d)\s*[xX]\s*(\d+)`／`\s[xX]\s*(\d+)` 这类上下文里当乘号；
    ④ **整机不折算**（Atlas 800I/800T、DGX、Mac、服务器只写"N 台"的，计台数不计卡数；`Atlas 300V` 是卡仍计卡数）；
    ⑤ 含"未填／未標"字样的片段要整段排除（否则「HUAWEI（華為）欄未填」会被读成有华为）；
    ⑥ **必须做自检**：如果原表里出现过"合计 N 张"之类的锚点，解析结果要能和它对上（本项目两校 38／100 全对）；
    ⑦ 出图前提示"张数≠算力"（消费级 RTX 会按张数被显著放大），并给"未标数量按 1 计"的敏感性对照。

15. **收到"某条轨迹／某张图有重复"这类反馈，先分层定位再改**：
    ① **数据层**是否有重复主体——把主体名归一后 `collections.Counter` 一验就知道（本项目 51 家无重名；
    18 个主体／42 条重复提交属"同一主体多次作答"，已在样本漏斗与护栏里并录并注明取值规则，不是要删的数据）；
    ② 若数据无重复，问题一定在**图上或文字里**：同一主体画了两组口径（主口径＋下限档）、
    同一张轨迹在两个 cell 各画一遍、或"缺口"（增量）与"需求总量"混成一条轨迹。
    ③ 改完顺手全篇 grep 旧措辞（`三张图`／`这两张图`／`重複畫` 之类），把说明文字一起对齐。

16. **同一主体的"不同层级"分别填报：以最新、层级更高的整体填报为准**（校方/机构口径，实测）：
    本项目澳门大学先由**智慧城市技術研究院（ISCT）**报了一份（用在 60+、缺口 100、2027/2029「>300／>500」），
    随后**学校本体**又报了一份完整的（用在 136、缺口 NA、2027「200–300P」、2029「>500P」），
    并要求"忽略院系级旧填报、澳大全部用最新填报"。
    做法：
    - **快照层**：按"去括号后的主体名 + 包含关系（`A in B` 或共同前缀）"归并到**层级最高的那个名字**，
      同一主体多份填报**只保留最新一条**（`(finished, createdAt)` 取大者），被剔除的写进快照
      `univ_superseded` 字段并在数据层逐条打印（谁在何时被谁取代）。
    - **实时层**：另建一个去重后的 DataFrame（本项目 `UNIV_LIVE`／`DFA`），
      所有按"校/家"统计的分布、饼图、卡数核算都改走它——否则同一所学校在**每一题**里都被计两次，
      而漏斗表里的"去重后主体"也要换成同一个归并键。
    - **坑**：归并键**不能**直接用会删地名后缀的 `norm_entity`（它把「澳門」当后缀删掉，
      「澳門大學」与「澳門城市大學」就混了）；要单独写一个只去括号、保留地名的 key 函数。
    - **连带更新**：主体数据一变，所有引用该校的图注、结论句、汇总表说明（乃至 Word/速览）都要重出，
      并在 README 写明"本期数字与上一期不可直接比较"。

17. **用户回传的「列重排」Excel 是列序契约，要用断言锁住**：把用户改过列序的文件读回来，
    生成时期望列序 = 用户栏序 + 新栏插入点，跑 `assert exp == list(new.columns)`（本项目「用户 94 → 期望 99」
    一次对上）；顺手把「新栏插在哪一栏之后」写进说明页。**别凭记忆重排**——用户是按自己的使用习惯排的。

18. **「跨类别重复（需求不重计）」必须按归一主体键算，不能沿用匹配到的那一行的值**：
    清单里同一主体跨类别出现时（本例 6 组），匹配只认**首次出现**的清单行，于是另一行上的"不重计"标记
    在主体行上就丢了（旧表整列为空）。要按归一键算出 `CROSS_DUP` 并回填到该主体的**所有**行，另给
    「清单其他出现位置」列。

19. **自报文本解析有两类必踩的误读**：
    - **叙述式作答**（高校把「3 billion tokens／month」写成整段推导）：正则取首个数字会把 token 数当 P 值
      （本项目实测把旅游大学读成 3.0/3.0/5.0/7.0 三个假数，真值是 0／66.7／116.3）。要先判叙述
      （长度 >40 或含「原表填答／估算」等），改取分析侧快照点值，并在说明页写清；
    - **哨兵值**：`-1`（新国都缺口）会被 `\d+` 读成 1.0、`NA`／`業務未上線` 要判空。
    - 双口径就给两列（中值口径／桶上限口径）**各自写清规则**：桶上限＝区间取上界、开口（`>nn`／`nn+`／`nn 以上`）
      以 nn 计、「小於 N」以 N 计、直填数字原值——别在同一列里混口径。

20. **产品名 ≠ 公司名：拿 App／产品名做别名前，必须在官方企业资料里核过**：本项目把问卷里的 `mFood`
    别到「澳門網絡傳媒發展有限公司」，实际 mFood 由「澳門智慧餐飲管理有限公司」营运
    （DSEDT PCET 认证名单 id=56：mFood APP／mfoodapp.com／hr@mfood.mo；id=5 的网络传媒营运的是
    「澳覓 APP」／aomiapp.com）。错的别名会连锁污染清单反馈覆盖、类别归属与需求合计。
    **核别名看官方企业简介的"产品／网站／邮箱域名"**，别只看名字像不像；改完要在两张表（明细＋清单）同时订正，
    并交代对上一版数字的影响。

21. **「1+4」这类政策分类：先本地规则、再对模糊项 deep research，并落一份「逐条依据＋来源＋信心」表**：
    本项目 119 条，先用关键词规则分（医药/生物→中医药大健康；银行/支付/投资→现代金融；旅游/航空/机场→
    综合旅游休闲；电信/软件/芯片→高新技术；公用事业/政府/医院→非1+4），再对 ~45 条模糊项**并行派子代理**查证；
    DSEDT《科技企业认证计划》(PCET) 的企业简介是最佳一手材料（含产品、网站、邮箱）。
    实测出现三处「名字带科技、主业不是科技」的修正：匯科（博彩设备→「1」综合旅游休闲）、
    澳門黌宮（中药保健品→「4」中医药大健康）、友信行／均安化工／澳运国际（传统行业→非1+4）——
    所以**不能只按名字或清单原类别拍**，信心低的行要显式标出来给用户复核。

22. **slim 之后要复核文件没被 JupyterLab autosave 写回**：本项目装好 slim 版（2.5 MB）约 10 分钟后，
    容器里同名 notebook 自己变回 6.4 MB 的未 slim 版——是**浏览器标签页持有的会话把内存里的旧内容自动保存回磁盘**。
    特征：mtime 无端变新、体积回跳、`metadata.signature` 消失、`_checkpoints/` 里躺着 Jupyter 的旧备份。
    处置：重新 slim 装回，**隔 20–30 秒再 `md5sum` 复核稳定性**；能先关掉相关标签页最稳。
    另：主机侧 `build_notebook.py` 若在同一轮里重跑，会覆盖仓库里那份**已执行**的 ipynb，
    切记它在执行前只是没有输出的骨架——落盘顺序永远是「执行→slim→装回→docker cp 回仓库」。

23. **用户回传的逐行标注（如「採信／不采信」）要按稳定键套回，并落成独立数据文件**：
    本项目用户在表里手标了 34 行 `採信=N`（同一主体多份填报的冗余行）。做法：
    ① **键选 `created_at`**（唯一、不随排序/新增而变），不要用行号或「主体名称」（同名多份会撞）；
    ② 套回后做 **1:1 校验**（`用户标记数 == 命中数`，本项目 34/34），并把未命中的键逐条打印；
    ③ 标记**落成 `trust_marks.json`**（`{created_at: "N"}`），脚本读它而不是硬编码——下一轮用户增量标注时只改这个文件；
    ④ 语义写进说明页：`N`＝不采信、空白＝采信（默认）、仅清单行留空；
    ⑤ **若某条标注与既有口径决策冲突，必须显式提示**（本项目用户把 2026-10-13 的澳大整体填报标了 N、保留 ISCT 旧填报，
    与其 3 天前「澳大一律用最新填报」相反）——照套用是尊重用户，但要在回复与说明页里点名，并给出「删掉该条重跑」的回滚方式。

24. **用户在数据表里手加的「合计行」和「枢辰表」：合计移出数据区、枢辰复现为独立 sheet，并与用户的数字逐格对数**：
    本项目用户回传件多了 2 行合计（在 209 行数据之下）和 4 张枢辰表。重建时：合计不放进数据区（否则排序/筛选被污染），
    改由匯總 sheet 的「合計」行承担；4 张枢辰按同样口径（`採信≠N` + 有具名主体 + 非测试占位、桶上限口径、主体按名称去重）
    重新算成独立 sheet，并**逐格核对**用户原枢辰数（本项目 6 个類別 + 7 个 1+4 分组全对上，只有新增答卷造成 +1/+0/+10/+50）。
    对数能立刻暴露两种错：我漏了筛选条件（把测试占位行的垃圾数字算进去，151 P 虚增）、或用户自己漏标（某主体全被排除）。

25. **清单「追加条目」的补丁必须幂等**：本项目的 `LIST_ADD`（新增 HKBN JOS）在清单一度回流之后**又跑了一遍**，
    结果清单变 120 条、同一主体出现两次。正确做法：追加前先算现有键集合，`if tkey(new) in 现有键 → 跳过并打印`；
    不要用「按 `_key` 去重」了事——那会把清单里合法的**跨类别重复行**（6 组 12 条）一起删掉。

26. **清单侧没有反馈记录（`—`）时，不要留空、也不要手改，按该行自身作答推断**：规则＝完成且四列齐→`有效（四列）`；
    完成但缺列→`已提交（僅 n 列）`／`已提交（未提供關鍵數據）`；未完成→`未完成提交`。
    这样「清单外主体」（Zhongshi）和「清单刚记 `—` 但新答卷到了」（澳门国际机场 2026-10-16）都能自动显示为「有效（四列）」，
    不必每轮手改；推断行数要打印出来（本项目 7 行），便于复核。

27. **把条形图换成饼图，不只是换 API——顺手查一遍「其他／未归类」占比**：
    用户要求「接受度改为饼图」时，饼一出来「其他／未归类 9.1%」就非常刺眼。回头看原始作答，5 条里 4 条其实可归类
    （「自有滿足」「數據敏感性」「費用…難以支撐」＝不需要／暂无需要；「待確認…」＝看情况），只有 1 条是答非所问。
    补 4 类关键词后「其他」降到 1.8%，而**愿意率不变**（46/55，因为被重归的都不在愿意档）——
    这类「只改小档、不动头条数字」的修正最安全，但必须在回复里明说改了哪几条规则。
    要点：① 单选题饼＝**家数占比**（分母＝该题有作答的完成样本），不是多选份额；② 同一道题若在别处也有归并函数
    （本项目 1.0 与 3.6 各一份 `_will`），**两处必须同步改**，否则两节口径打架；③ 扇区标签写 `檔名\n家数（%）`、
    图注用 `fig.text` 放在坐标区下方（`tight_layout(rect=(0,0.05,1,1))`），不要遮住扇区。

28. **换了图／改了口径，记得回头 grep 文档里写死的百分比**：本项目 Word 速览的「§五」表格是数据驱动的，
    但正文仍写死「另有约 3.8%…3.8%」——图换了、数变了，正文却不跟着变。改法：把那段也改成从
    `key_numbers.json` 现算（`detail` 四档 → 百分比），并加一条「其他档非空才出现」的条件句。
    交付前统一 grep 一遍 `83.3%`／`45 / 54`／`3.8%` 这类字面量，确认只剩历史记录里该保留的。

## 调研发起方给的「目标清单」× 问卷反馈（覆盖面交付）

用户常拿来一份**目标主体清单**（此处是扫描件转写的《建議名單》：118 条 / 五类 / 原件日期），要求
「标出哪些有反馈、给反馈图、按这 5 类统计问卷需求」。做法：

1. **清单也要有唯一真源**：把 CSV 原样内嵌进 notebook（JSON 字符串占位符），运行时**优先读卷内文件**、
   回退内置副本——和快照同一套规矩，否则清单改一次就要重建 notebook。
   **坑**：卷内那份（如 `/home/jovyan/work/澳门调研主体清单.csv`，在 docker volume 里）优先级更高，
   改了仓库里的 CSV 却忘了 `docker cp` 覆盖卷内那份，notebook 会静默继续用旧清单（本项目 118→119 时踩到）。
2. **匹配口径写清楚**：名称归一＝`NFKC → 繁转简 → 去括号标点 → 去公司后缀 → 小写`；
   依次 **精确 → 人工别名（`ALIAS`，每条注明依据）→ 包含式（≥3 字）→ 共同前缀（≥5 字）**。
   别名是必要的（本例：`mFood`＝澳門網絡傳媒發展、`Shiji (Macau) Limited`＝石基（澳門）、
   問卷把「股份有限公司」误填成「股份有效公司」等），但必须逐条留依据、可审计。
3. **繁简转换要有**：容器常无 opencc，notebook 用内置回退字表。字表要按**问卷文本 ∪ 清单文本**生成
   （本例把 337 字扩到 391 字，补上 麥/門/顥/黌/甡 等清单用字），否则「澳門××」匹配不上「澳门××」。
4. **反馈分两条来源**，都要标：① 问卷有具名提交（含只提交未填关键数据、以及内地/非本地主体这类「口径外」提交）；
   ② 走访/深研（该主体在调研目录下有专门研究件，手工维护一份 `主体 → 研究件路径` 表）。
5. **需求只计一次**：清单里常有跨类别重复（本例 6 组 12 条），需求按**主体**归首次出现的类别，
   另给「含重复」对照列；再给一张**清单外但有填答的主体**表做对账——「清单内＋清单外＝全样本合计」必须逐项对上。
6. **反馈图 + 需求图**：反馈图＝按类别的「两者／仅问卷／仅走访／无反馈」堆叠 + 同一分母下两条渠道的覆盖；
   需求图＝四指标（在用/近期缺口/1 年/3 年）× 类别，主口径剔越界主体，并单独注明被剔者的量级。
7. **交付三件**：逐条标记的 CSV（UTF-8 with BOM）+ XLSX（明细 + 按类别汇总，带筛选与冻结窗格）+
   notebook 里可复跑的 1.9 小节；最后附「无任何反馈」清单（按类别/原定调研方式）供催覆。

### 主体级合并总表（两份问卷导出 × 目标清单，一张宽表）

用户会要一张「**逐主体 × 全部题项**」的宽表（本项目 209 行 × 99 列）。做法与要点：

1. **列名按题号对齐**：两卷同题题号常不同（在用 `q4↔q7`、缺口 `q11↔t4gv…`），写一张显式映射表并由脚本
   生成「统一列名 ↔ 两卷原栏（qid）↔ 题面」对照页（本项目 61 组）；CTA／感谢页列直接丢弃。
2. **逐行合并保留全部脏数据**：含未完成、测试占位、无主体名、内地非本地主体的行都保留，另加
   `行來源／問卷別／錄入標記／清單匹配狀態` 护栏列——**不要在执行层静默删行**，让用户自己筛。
3. **清单侧列加前缀**：清单的数值列与问卷自报列同名（在用/缺口/2027/2029）→ 改成 `清單·…（快照）`，
   避免与自报值混淆；再另给「解析值」「桶上限口径」等派生列。
4. **补行与对账**：清单里问卷完全没覆盖的主体各补一行（问卷列留空）；收尾跑三条断言——
   清单条数 = 由问卷匹配条数 + 由清单补行条数；应补未补 = 0；「清单有反馈但本次 CSV 未见」逐条打印。
5. **列序以用户回传件为准**（见坑 #17）；改列序/加列后**先跑一次与上一版的逐列 diff**，把"哪些行、哪些列
   变了"打印出来（本项目改动收敛到 4 类：跨类别重复标记、两条解析值误读修正、种远反馈状态、mFood 归属），
   既自证无副作用，也方便向用户交代。
6. **发现旧版匹配错误就当场订正并写进说明页**（本项目：mFood 归属、南芯省市用字、种远集团与制造厂、
   新版清单新增 HKBN JOS）——表内自洽优先，同时在 README 注明"哪些上游产物（notebook 1.9／清单导出／速览）
   尚未回流、重出时数字会怎么变"。
